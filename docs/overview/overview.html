How a request travels

Understand

Sonnet reads your request and the project's two-line brief.

Locate

Haiku searches the code map and returns exact file and line.

Plan

Opus writes a short plan, only for multi-file or design work.

Build

The smallest correct change, reusing helpers that already exist.

Verify

Haiku runs the narrowest test that proves the change works.

Learn

A correction you make twice becomes a lasting project rule.

Why it works

Every reply in a session re-reads the whole conversation, plus a fixed floor of 12,000 to 14,000 tokens of instructions. All of it is paid at the main model's price.

So the main seat sets the bill. Tokenwise gives that seat to Sonnet, sends reading and test runs to Haiku, and calls Opus only for the moments that need its judgement.

Habits that keep sessions cheap

  • Name the file and function. One open beats a search.

  • Paste the decisive error line. Not the whole log.

  • Say when it's done. "Done when the pricing tests pass."

  • One topic per session. Use /clear when you switch.

Safe by design

  • No hooks. Nothing runs on its own.

  • Least-privilege agents. Each gets only the tools it needs.

  • Secrets stay out. Never mapped, never read.

  • Never overwrites. The installer only adds files.
